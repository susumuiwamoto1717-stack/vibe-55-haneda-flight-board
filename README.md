# 羽田発着案内板 ✈️ — HANEDA FLIGHT BOARD

羽田空港の発着情報を、空港の掲示板（FIDS）スタイルで表示するWebアプリ。
定期ダイヤを羽田公式サイトから自動取得し、**風向き・時間帯から滑走路（A/B/C/D）を予測**して表示する。
スポッターや旅行者が「今どの滑走路を使っているか」をひと目で確認できる。

作成: 2026-07-01〜07-03 / 羽田空港での実利用がきっかけ。

**公開URL**: https://vibe-55-haneda-flight-board.vercel.app  
（GitHub Actions が**毎時**羽田公式からダイヤを取得しコミット → Vercel が自動デプロイ。公式サイトへの負荷を1時間1回に抑えた構成）

**ローカル版**: `python3 server.py` → http://localhost:8787（🔄 更新ボタンで手動取得可）

## 主な機能

| 機能 | 説明 |
|---|---|
| 掲示板UI | 黒地×アンバーの FIDS 風デザイン、ライブ時計 |
| ARR / DEP ビュー | 到着・出発を切り替えて表示 |
| 滑走路予測 (RWY) | 北風/南風/南風15–19時ルールで便ごとに自動割当 |
| 滑走路別ビュー | A/B/C/D を選ぶとその滑走路の離着陸を時刻順に表示 |
| 配置図 SVG | タップで滑走路を選択、現在使用中を着色 |
| 日跨ぎ対応 | 基準時刻から12時間先まで、翌日分も続けて表示 |
| 欠航・遅延表示 | 欠航＝赤行＋理由、遅延は公式判定を忠実に反映 |
| 航空会社名 | 3レターコードを日本語名に変換（主要50社超） |
| 🔄 更新ボタン | ローカル環境でワンクリックで最新ダイヤを取得 |

## 起動方法

### 推奨：ローカルサーバー経由（フル機能）

```bash
git clone https://github.com/susumuiwamoto1717-stack/vibe-55-haneda-flight-board
cd vibe-55-haneda-flight-board
python3 server.py
# → ブラウザで http://localhost:8787 を開く
# → 右上の「🔄 更新」ボタンで最新ダイヤを取得できる
```

> `file://` で直接 index.html を開いても見られるが、更新ボタンは動作しない。

### 自動更新（任意）

```bash
bash auto_update.sh          # 1時間ごとに自動取得（負荷配慮の既定値）
bash auto_update.sh 600      # 短くしたい場合（例: 10分ごと）
```

画面は5分ごとに自動リロードする（タブ・フィルタ・風向は保持）。

### 機材（機種）を表示したい場合（任意）

羽田公式APIには機種情報がないため AeroDataBox（RapidAPI 無料枠）を使う。

1. https://rapidapi.com/aedbx-aedbx/api/aerodatabox → Basic（無料）を Subscribe
2. 取得したキーを以下のいずれかで設定:
   ```bash
   export AERODATABOX_KEY="取得したキー"
   # または aerodatabox_key.txt にキーを書いて保存
   ```
3. `python3 fetch_aircraft.py`（server.py 経由なら更新ボタンで自動起動）

## 滑走路運用ルール

国土交通省「羽田空港のこれから」に基づく予測ロジック。

| 風向き | 時間帯 | 着陸 | 出発 |
|---|---|---|---|
| 北風 | 全時間 | A(34L) / C(34R) | D(05) / C(34R) |
| 南風 | 〜14時・19時〜 | B(22) / D(23) | C(16L) / A(16R) |
| 南風 | 15〜19時（新ルート）| C(16L) / A(16R) | A(16R) / B(22) |

> 便ごとの2本振り分けは目安。実際の運用は管制官の判断による。

## 羽田公式フライトAPI（非公開エンドポイント）

`fetch_haneda.py` が使用。キー不要。

- `POST https://tokyo-haneda.com/app/api/v2/flight/search`
- 必須ヘッダ: `Content-Type: application/json`, `X-Requested-With: XMLHttpRequest`,  
  `Origin / Referer: https://tokyo-haneda.com`, ブラウザ風 UA（これらが無いと403）
- 当日の国内＋国際で約 1,300 便を取得

### データ取得ポリシー（非公開APIとの付き合い方）

このAPIは「隠されたもの」ではなく、羽田空港公式サイトのフライト情報ページを
ブラウザで開けば誰でも自動的に呼ばれる通信を、プログラムで再現しているもの。
認証の回避や非公開情報へのアクセスは行っていない。
ただしドキュメント化された公開APIではないため、次の方針で運用する。

**考え方（判断軸）**

| 軸 | 本アプリの位置づけ |
|---|---|
| 負荷 | 人間がブラウザで閲覧するのと同程度以下に抑える（下記の実装参照） |
| データの性質 | フライトダイヤ＝公共性の高い事実情報。個人情報・創作物ではない |
| 用途と規模 | 個人〜小規模利用。商用化・大規模展開する場合は正規のデータ提供元へ乗り換える |
| 透明性 | データ元と制約を本READMEに明記する |

**負荷を抑えるための実装（コードで強制）**

- **取得は1時間に1回**: GitHub Actions の定期実行を毎時に設定。公開URLの閲覧者が増えても、公式サイトへのアクセスは増えない（取得を1か所に集約し、キャッシュ済みの `flights_data.js` を配信するだけ）
- **ローカルの更新ボタンにもレート制限**: `server.py` が最短60秒に1回に制限（超過は 429 を返す）。連打やスクリプトからの過剰リクエストを防ぐ
- **リクエスト間スリープ**: `fetch_haneda.py` は1回の取得内でもリクエスト間に 0.4秒待つ
- **多重実行の防止**: 更新処理が実行中の間は新しい更新を受け付けない

**仕様変更への備え**

公開契約がない以上、予告なくエンドポイントが変わる・止まる可能性がある。
そのため `fetch_haneda.py` は「1件も取得できなかった場合は既存の `flights_data.js` を
上書きせず異常終了する」変更検知を実装しており、仕様変更時にも表示データが壊れない
（GitHub Actions 側もこの終了コードで失敗を検知できる）。

> まとめ: 公開ページを人間並みの頻度で読む範囲に留め、負荷制御をコードで強制し、
> 壊れたら静かに止まる。商用・大規模化の際は正規APIへの移行を検討すること。
